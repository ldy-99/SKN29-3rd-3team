# A. PM + React 작업 가이드

## 1. 역할 요약

PM + React 담당자는 사용자가 서비스를 이해하고 입력을 완료할 수 있도록 화면 흐름과 입력 경험을 설계하고 구현합니다.  
4차 프로젝트에서는 모든 기능을 한 번에 완성하기보다, P0 흐름이 끊기지 않도록 “가입 → 프로필 입력 → 진단 실행 → 결과 확인 → 챗봇 질문” 경로를 먼저 안정화합니다.

## 2. 우선 책임

| 영역 | 할 일 |
|---|---|
| 제품 범위 | P0, P0.5, P1을 구분하고 화면에 들어갈 기능을 조절합니다. |
| 입력 화면 | 사용자에게 필요한 정보를 단계별로 받습니다. 한 화면에서 과도하게 묻지 않습니다. |
| 결과 화면 | 추천 공급유형, 누락 정보, 판단 근거를 사용자가 이해하기 쉽게 보여줍니다. |
| React 구현 | Django 공개 API와 연결되는 화면, form, 상태 관리를 구현합니다. |
| UX 수용 기준 | “사용자가 다음에 무엇을 해야 하는지”가 보이는지 확인합니다. |

## 3. 작업 순서

### Day 1~2

| 순서 | 작업 |
|---|---|
| 1 | P0 화면 목록을 확정합니다. |
| 2 | 프로필 입력 필드를 API 계약 문서와 맞춥니다. |
| 3 | 필수값과 조건부 입력값을 화면에서 구분합니다. |
| 4 | Django 더미 API 또는 fixture 응답으로 화면을 먼저 연결합니다. |
| 5 | 결과 화면에 필요한 데이터 구조를 B, C 담당자와 맞춥니다. |

### Day 3 이후

| 순서 | 작업 |
|---|---|
| 1 | 회원가입/로그인 화면 흐름을 API와 연결합니다. |
| 2 | 프로필 저장·수정 화면을 구현합니다. |
| 3 | 전략 진단 요청과 결과 화면을 연결합니다. |
| 4 | 챗봇 화면에서 Django proxy API를 호출합니다. |
| 5 | 오류, 로딩, 빈 상태를 정리합니다. |

## 4. 화면 구성 기준

| 화면 | 최소 포함 내용 |
|---|---|
| 로그인/회원가입 | 입력값 검증, 실패 메시지, 로그인 후 이동 |
| 프로필 입력 | P0 필드, 조건부 필드 안내, 저장 버튼 |
| 진단 실행 | 저장된 프로필 기반 실행, 공고 입력 fallback |
| 결과 목록 | 최근 진단 결과, 생성일, 추천 공급유형 |
| 결과 상세 | 추천 Top N, 점수/근거, 부족한 정보, 다음 행동 |
| FAQ 챗봇 | 추천 질문, 사용자 질문, 답변, 참고 자료 |

## 5. API 호출 기준

React는 FastAPI를 직접 호출하지 않습니다. 항상 Django API를 호출합니다.

```text
React 화면
  → Django DRF API
  → 필요 시 Django가 FastAPI 내부 호출
  → React는 Django 응답만 표시
```

상태 변경 요청에는 인증 쿠키와 CSRF 토큰 처리가 필요합니다.

```javascript
fetch("/api/user/profile", {
  method: "PATCH",
  credentials: "include",
  headers: {
    "Content-Type": "application/json",
    "X-CSRFToken": csrfToken
  },
  body: JSON.stringify(payload)
})
```

## 6. UX 체크리스트

| 체크 | 질문 |
|---|---|
| 입력 부담 | 사용자가 처음부터 너무 많은 정보를 요구받지 않는가? |
| 안내 | 필수값과 선택/조건부 값이 구분되어 보이는가? |
| 오류 | 잘못 입력했을 때 무엇을 고쳐야 하는지 바로 보이는가? |
| 결과 | 추천 이유와 부족한 정보가 함께 보이는가? |
| 다음 행동 | 사용자가 결과를 보고 다음에 무엇을 할지 알 수 있는가? |

## 7. PR 전 확인

- API 필드명이 `01_API_데이터_계약_명세.md`와 일치하는지 확인합니다.
- FastAPI 직접 호출 코드가 없는지 확인합니다.
- 로딩, 실패, 빈 결과 화면이 있는지 확인합니다.
- 화면 변경 PR에는 캡처를 첨부합니다.
- API 계약 변경이 필요하면 B 담당자와 먼저 합의합니다.
