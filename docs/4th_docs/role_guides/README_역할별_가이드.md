# 역할별 작업 가이드

## 1. 사용 목적

이 폴더는 4차 프로젝트에서 각 역할을 맡은 팀원이 자신의 업무 범위, 우선순위, 협업 방식, 산출물을 빠르게 확인하기 위한 가이드입니다.  
세부 계약은 상위 명세 문서(`00~04`)를 기준으로 하고, 이 문서는 실제 작업할 때 보는 실행 안내서로 사용합니다.

## 2. 역할 구분

| 역할 | 주요 책임 | 참고 파일 |
|---|---|---|
| A: PM + React | 제품 범위, 화면 흐름, 사용자 입력/결과 UX | `A_PM_React_가이드.md` |
| B: Tech Lead + Integration | API 계약, 통합 기준, PR·CI·문서 정리 | `B_TechLead_Integration_가이드.md` |
| C: Django API | 인증, 세션, DB, 공개 API, 사용자 소유권 | `C_Django_API_가이드.md` |
| D: AI/FastAPI/RAG | 기존 3차 AI 재사용, adapter, 챗봇/RAG 연결 | `D_AI_FastAPI_RAG_가이드.md` |

## 3. 공통 작업 원칙

| 원칙 | 설명 |
|---|---|
| 계약 먼저 | API 필드명, null, enum, fixture를 먼저 맞춘 뒤 기능을 붙입니다. |
| 직접 연결 금지 | 브라우저는 Django API만 호출합니다. FastAPI는 Django 내부 호출 대상으로 둡니다. |
| 작은 PR | 한 PR에는 하나의 목적만 담습니다. 리뷰 가능한 단위로 나눕니다. |
| fixture 기준 개발 | 실제 AI가 늦어져도 React와 Django는 fixture로 먼저 붙입니다. |
| 모르는 값 보존 | `null`, `0`, `false`를 섞지 않습니다. 사용자가 모르는 값은 `null`로 둡니다. |

## 4. 하루 작업 흐름

```text
오늘 할 일 확인
  → 관련 명세 문서 확인
  → 계약 변경 여부 확인
  → 작은 단위로 구현
  → 로컬 검증
  → PR 작성
  → 리뷰 반영
  → 결정/변경 사항 문서화
```

## 5. 역할별 문서 사용법

1. 먼저 본인이 맡은 역할 가이드를 읽습니다.
2. 작업 중 API, 필드, null, 인증, AI 호출 방식이 나오면 상위 명세 문서를 함께 확인합니다.
3. 문서와 구현이 다르면 혼자 판단하지 않고 담당자에게 공유합니다.
4. 변경이 확정되면 코드와 문서를 함께 수정합니다.
