# 03. 실행·협업 가이드

## 1. 문서 목적

본 문서는 4차 프로젝트의 10영업일 실행 계획, 역할, Git·PR 규칙, CI 기준, Day 1~2 Gate를 정의합니다. 기능 개발 전에 계약과 통합 기준을 먼저 고정하고, 이후 병렬 작업이 서로 충돌하지 않도록 관리합니다.

| 항목 | 내용 |
|---|---|
| 통합 전 참조자료 | 기존 실행 협업 가이드와 Day1-2 착수 문서를 통합 반영 |
| 적용 범위 | 일정, 역할, PR, CI, Gate, 실패 시 조정 |
| 우선 독자 | 전체 팀원 |

## 2. 실행 원칙

| 원칙 | 설명 |
|---|---|
| 계약 먼저, 기능 나중 | API·필드·null·fixture를 먼저 고정합니다. |
| 상위 Gate 우선 | Gate를 통과하지 못하면 하위 기능을 늘리지 않습니다. |
| 병렬 작업 최소 충돌 | 파일 소유권과 PR reviewer를 명확히 둡니다. |
| Trunk-based Development | 짧은 브랜치, 작은 PR, 빠른 리뷰를 유지합니다. |
| Done의 기준 | 코드 작성이 아니라 산출물·리뷰·검사 통과입니다. |

## 5. Day 1~2 우선순위

```text
P1  범위·역할·저장소 구조 고정
 ↓
P2  API 계약·null 영향·fixture 고정
 ↓
P3  병렬 검증
    ├─ React→Django 더미 연결
    ├─ FastAPI HTTP/local 실행 비교
    └─ CI·Docker·AWS·RAG 준비
 ↓
P4  AI 실행 방식 하나 확정
 ↓
P5  Day 3 작업 인계
```

## 6. Git 규칙

| 항목 | 기준 |
|---|---|
| 기준 브랜치 | `main` |
| 전략 | Trunk-based Development |
| 브랜치 이름 | `feat/...`, `fix/...`, `docs/...`, `chore/...` |
| PR 크기 | 작게, 빠르게 리뷰 가능한 단위 |
| 커밋 메시지 | 변경 목적이 드러나게 작성 |

## 7. PR 필수 항목

모든 PR에는 다음 항목을 포함합니다.

```text
## 목적
## 관련 Issue
## 변경 내용
## 테스트 결과
## API·DB·환경변수 변경
## 영향 범위
## 화면 캡처 또는 해당 없음
## 배포·롤백 영향
```

## 8. 파일 소유권과 리뷰

| 영역 | 주 담당 | 필수 리뷰 |
|---|---|---|
| React 화면 | A | B |
| Django API·DB | C | B |
| FastAPI·AI·RAG | D | B |
| API 계약·fixture | B | A·C·D |
| 배포·CI | B | C·D |

API 계약, DB migration, 환경변수, 인증 정책 변경은 단독 병합하지 않습니다.

## 9. CI 기준

| 영역 | 최소 검사 |
|---|---|
| React | lint, build |
| Django | migration check, unit test, API fixture test |
| FastAPI·AI | import test, fixture diagnosis test, RAG smoke test |
| 문서 | 링크/파일명 확인, 실행 방법 최신화 |

## 10. 작업 상태 규칙

작업 상태는 `Ready → In Progress → Review → Done`과 `Blocked`만 사용합니다.

| 규칙 | 설명 |
|---|---|
| In Progress 제한 | 팀원별 주 작업은 하나만 둡니다. |
| Blocked 처리 | 30분 이상 혼자 보유하지 않습니다. |
| Done 기준 | 코드 작성이 아니라 리뷰와 검사 통과입니다. |
| 계약 변경 | 계약 PR 없이 임의 구현하지 않습니다. |

## 11. 실패 시 조정 기준

| 상황 | 조정 |
|---|---|
| Day 2에 계약 미확정 | 기능 개발을 늘리지 않고 계약·fixture부터 고정합니다. |
| FastAPI 연결 불안정 | HTTP/local 중 안정적인 방식 하나로 축소합니다. |
| PDF 분석 지연 | 수동 공고 입력 fallback으로 진단 흐름을 유지하되, `/api/pdf/analyze` P0 계약은 유지합니다. |
| ChromaDB 준비 실패 | 챗봇 scope를 고정 질문 smoke test 수준으로 축소합니다. |
| 배포 지연 | 로컬 실행 재현성과 CI 통과를 우선 확보합니다. |

## 12. 최종 Gate

P0 완료 기준은 다음과 같습니다.

| 항목 | 완료 기준 |
|---|---|
| 새 clone 실행 | README 기준으로 실행 가능 |
| 인증 | signup/login/logout/me 동작 |
| 프로필 | GET/PUT/PATCH 동작 및 사용자 소유권 보장 |
| 진단 | 저장된 프로필 기반 전략 생성 |
| 결과 | 목록·상세 조회 가능 |
| 챗봇 | React 화면에서 질문·답변 가능 |
| 배포 | P0 배포 확인 또는 재현 가능한 배포 계획 |
